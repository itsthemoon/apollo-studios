Features

Twelve tools, described the way they are actually built. Where a piece is a cheap approximation of something expensive, this page says so instead of dressing it up.

Every module below is a pure function over Float32Array or plain note objects. None of them touch the DOM, none of them fetch, and each has a Node self-test that runs in the suite before the browser is involved. If a control misbehaves, the bug is in the wiring, not in the maths — because the maths is already asserted.

Autotune

Pitch detection runs normalized autocorrelation per 2048-sample frame with a 512-sample hop. Frames whose clarity falls under half are discarded, and neighbouring frames within 50 cents of each other merge into one note. That note list is what tuning operates on: each note is moved toward the nearest pitch class in the chosen scale, by a strength proportional to the dial.

Strong settings are deliberately robotic. Weak settings leave the vibrato mostly intact and only pull the entries and exits. Nothing is pitch-shifted in the time domain by a phase vocoder; the take is resampled along a per-sample speed curve, so extreme settings thicken the top end the way tape varispeed does.

Harmonies

Six interval presets: diatonic thirds, fourths, fifths, an octave down, an octave up and a wide stack. Each interval becomes its own copy of the note list, transposed and labelled, with a gain and a millisecond spread so the copies do not stack into a single comb-filtered lump.

Harmonies follow the notes you sang rather than the chord grid. That means a third above is a real third even when the key changes mid-phrase, but it also means a harmony can land on a note you did not intend if the source note was wrong. Fix the take before adding parts.

Voice characters

Each character is a tuple: a pitch shift in semitones, a treble tilt, a soft drive amount and a breath-noise mix. Pitch is a resample ratio of 2 ** (semis / 12); the tilt is a single high shelf; the drive is tanh with a scaled input; the breath is mixed noise under the signal.

It is a character kit, not a formant shifter. The shifts change the whole formant picture along with the pitch, which is why the settings stop at about an octave and why a big downward shift sounds like a slower singer rather than a different person.

Stem split

A frame-based median split at 2048/512. For each frequency bin, the median across the neighbouring frames is treated as the harmonic estimate; the residual is the percussive part. Both stems come back at the original length and recombine sums them to within a thousandth of the input.

That is a two-bus separation with no model, no training and no per-instrument awareness. On a solo vocal it works as a de-noise and de-breath tool. On a dense mix it smears, and on anything with a lot of low mid it leaves artefacts. The FAQ has a longer answer on why it is like this.

Beat generator

Four genres, each with a tempo, a swing amount and three synthesized voices: a pitch-swept sine kick, a noise-burst snare with a body tone under it, and a highpassed noise hat. Output length is bars against the genre tempo, four beats to the bar, and the render is deterministic — the same genre and bar count gives the same samples every time.

There are no samples in the repository. Every drum hit is arithmetic, which keeps the folder small and the build absent, and means the kit is a sketch pad rather than a drum library.

Melody generator

A seeded mulberry32 walk. The generator takes a root, a scale, a step count and a tempo, then moves through scale degrees by one or two positions at a time, staying inside the key. The same seed reproduces the same line exactly, so an idea survives a reload.

It does not model phrase shape or contour. Lines wander. Treat the output as material to keep three bars of, not as a finished top line.

Chord generator

Triads stacked from scale degrees, one per bar, seeded the same way. Because the triads are built inside the scale, they stay functionally coherent in the key even when the voicings are plain.

Every chord is a root-position triad. Inversions are something you do by ear afterwards with the note editor.

Automix

Two parts. The first suggests a partial master setting derived from the genre's brightness and density, which is a starting EQ curve and compressor setting rather than a mix. The second, balance, takes a set of track levels and returns per-track trims that pull them toward a common target, clamped between -24 and +12 dB and never boosting the loudest track.

It is a rule of thumb written as code. It has no idea what is in the tracks, so it will happily make a quiet, important part louder than it should be.

Mastering chain

The chain order is fixed: EQ, compressor, loudness normalization, limiter. Bands are RBJ biquads — highpass, lowpass, peaking and shelves — set from the patch. The compressor has threshold, ratio, attack, release and makeup. Normalization brings the RMS to the target, and the limiter sits on the ceiling with lookahead.

After the chain, the meter measures the true output peak rather than the pre-limiter value, so the readout is what the file will contain. A neutral patch reduces to something very close to transparent, which the test asserts.

Presets

Patches are versioned JSON: tuning, master bands and compressor, ceiling, target loudness, vocal gain and reverb mix. validatePatch rejects the wrong version, an amount outside zero to one, more than eight bands, non-finite numbers and a missing name. Import goes through the same validator, so a malformed file is refused whole rather than applied until the first bad key.

Six factory patches ship in presets/builtin.json. Export writes your own; nothing is sent anywhere to do it.

WAV export

16-bit stereo PCM with a byte-exact 44-byte RIFF header, at 44.1 or 48 kHz. Samples are rounded and clipped to the int16 range. The tests check the magic, the channel count, the bit depth, the rate and the exact body length, then write a real file and read it back.

The bit-depth selector offers 24-bit but the encoder writes 16. That is a known gap, not a hidden one.

Project save

A project file holds the take, the notes and the patch in one JSON document, saved through the browser's download shelf and reopened with a file picker. It is intentionally the same shape as the preset file plus the audio, so a project can be read by hand.

Sample rate travels with the take. Opening a project recorded at another rate warns before it reloads, because a mismatch quietly detunes everything.
