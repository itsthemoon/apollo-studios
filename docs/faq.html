FAQ

The questions that decide whether this tool is for you, answered before you invest an evening in it.

What licence is it under?

MIT. The full text is in LICENSE: use it, modify it, redistribute it, sell something built with it, keep the copyright line. There is no contributor licence agreement and no dual licence to negotiate.

The one thing MIT asks is that you do not hold the author liable when it misbehaves. Given that the export path writes raw PCM from JavaScript in a browser tab, that clause is doing real work.

Where does my audio go?

Nowhere. Capture, pitch analysis, tuning, harmonies, mastering and WAV encoding all run in the page. The only network request the studio makes after load is none at all, because there are no fonts, no CDN scripts and no analytics.

The static server is loopback and has no logging or upload route. You can pull the ethernet cable after the page loads and keep working, including exporting. The one place your audio reaches the disk is the download shelf, when you press export or save.

That also means no sync, no share links and no backup. If you want the project on another machine, carry the JSON file yourself.

Why is the stem split so crude?

Because a real separator is a trained model of several megabytes, usually a web assembly build of an inference runtime, and a model would have broken the two rules this project set: no build step and no runtime dependency. The split is a frame-median harmonic and percussive decomposition — cheap, explainable, about forty lines, and it recombines to the original within a thousandth.

What that buys you: on a solo vocal it removes breaths, room and mouth noise well enough to work with. What it costs: on a dense mix it smears transients, thins the low mid, and leaves artefacts that sound like a bad MP3. It is a filter with a name, not a stem separator, and the UI never calls it one.

If you need real separation, run a model elsewhere and import the parts. The project has a place for that in future, not a promise of it now.

Is it really open source, or source-available?

Open source under an OSI licence, with the whole working app in the repository — not a shell around a hosted service. There is no paid tier, no account server and no feature held back for a cloud build.

How does it relate to BandLab?

It is independent. BandLab's web studio was studied as a shipped product, and the notes are in docs/bandlab-rea-notes.md. No BandLab code, preset data, names or assets are in the tree; the DSP is textbook autocorrelation and published RBJ biquads.

The result is a much smaller tool. There are no loops, no collaboration, no cloud projects and no mobile app.

Why 24-bit in the menu if the file is 16-bit?

The selector was built ahead of the encoder and never finished. encodeWav writes int16 only, so choosing 24-bit currently changes nothing about the output. It is listed as a known gap in the README rather than quietly removed, because the fix is small and someone may want it.

Does the microphone work in every browser?

Capture needs getUserMedia in a secure context. Loopback and localhost qualify; a LAN address over plain HTTP does not, so on another device serve over TLS or use the demo. Safari's MediaRecorder support is the thinnest of the three engines, which is what the ScriptProcessorNode fallback exists for.

On iOS the tab can be suspended mid-take by the system. The take survives if the page is not reloaded, but a long session is better on a desktop.

Can I use the output commercially?

Yes. MIT covers the code and the rendered audio is yours; there is no attribution requirement in the licence and no royalty. Credit is welcome and not required.

Why is there no build step?

So that what runs is what you can read. There is no transpile, no minify and no generated bundle — open js/tune.js in a text editor and it is the file the browser executed. It also means the folder runs from any static host, and that a fork stays reviewable.

The cost is no TypeScript and no tree shaking. At this size neither is missed.

How do I contribute?

Read CONTRIBUTING.md. Short version: run node scripts/test.mjs before and after, keep new modules pure and covered by a self-test, and do not add a dependency without saying why in the pull request. Bug reports with the exact steps and the console text are more useful than a feature request.

What is definitely missing?

Undo across panel operations, real stereo take handling, marker and region editing, MIDI import, and any form of separation that deserves the name. The README keeps a live list of gaps; it is not a roadmap with dates.
