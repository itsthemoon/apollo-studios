Getting started

Apollo Studios is a static folder. There is nothing to install, nothing to compile, and no service to sign into. You need a browser that can open a local page and, if you want to sing, a microphone.

1. Serve the folder

The page uses ES modules, so file:// will not load it. Serve the directory over loopback with anything that speaks HTTP. The repository ships a dependency-free server purely so nobody has to think about this:

node scripts/serve.mjs

That listens on http://127.0.0.1:4173/. Open it and the landing page loads; the studio is at /app.html. The landing header links every one of these pages, so the site stays joined up.

Any other static server works. Python's http.server, a Bun script, or the dev server of an editor will all do, because the site is only HTML, CSS, JS and one JSON file of factory presets.

2. Open the studio

Go to /app.html, or press Open the studio on the landing page. The transport sits at the top: record, play, stop, and the tempo and key controls that tuning is measured against.

If you have no microphone, or do not want to use one, press Load demo in the header. It synthesizes a short sung phrase with real pitch content, so every control downstream is usable in a few seconds. The demo is the same path the test suite exercises, which is why the tests can assert note counts and pitches without a room to record in.

3. Make something

Sing or load the demo, then work left to right through the panels. Tuning takes a strength value between zero and one: at zero the take is untouched, at one every note lands on the nearest legal pitch in the key. Pick a scale that fits the melody before pushing that dial, or the tune will sound like it is fighting you.

Presets carry the tuning, the vocal character and the whole master setting. The factory patches are deliberately mild; the interesting ones are the changes you make and then export as your own.

4. Export

Export WAV renders through the master chain and hands you a 16-bit stereo file at 44.1 or 48 kHz. Nothing is written to the disk until you click, and the browser's download shelf is the only place the file appears.

Watch the meter while the chain runs. The peak readout is measured after the limiter, not before, so a ceiling of -1 dB means the file leaves at -1 dB.

Requirements

BrowserChromium, Firefox and Safari from the last two years. Microphone capture needs a secure context, which loopback satisfies.
Node22 or newer, but only if you use the bundled server or the test suite. The studio itself does not need Node at runtime.
PermissionsMicrophone access is requested once, on the first record press. Denying it leaves the rest of the studio intact.

Verify the copy you have

If you cloned this from anywhere, run the suite before trusting it:

node scripts/test.mjs

It exits zero only when all four module self-tests pass, the audio path behaves, the WAV header is byte-correct and the site serves. Anything else is a real failure, not a warning.
